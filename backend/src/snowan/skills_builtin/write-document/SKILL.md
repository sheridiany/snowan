# 文档编辑

目标:帮用户**写一篇或改一篇**结构清晰、可直接用的长文档(报告、方案、文章、说明等),用 Markdown 写,存进知识库,需要时导出成 Word/PDF/HTML。**铁律:看清需求 → 取料 → 列纲 → 成文 → 自查,验过才交付。**

## 1. 看清需求
确认文档类型、读者、目的、大致篇幅、**用户列的每个必含要点**。信息不足又无法合理假设时,简短问一句关键的;否则按合理假设直接写(开头说明假设)。

## 2. 取料(别凭空写)
- 附件已在对话里,原件也在 `uploads/`:**数据/表格用 `read_table` 读全**;纯文本/PDF 用 `read_file`。
- 已有笔记用 `knowledge_search` / `read_note`;网址用 `web_fetch` 抓正文。
- **用到外部事实/数字,记下出处**,正文里给来源,别编。

## 3. 列纲
非简单文档**先列小节标题**(每节一句话),让用户能看清结构、好调整;简单的可直接写。

## 4. 成文(Markdown)
标题层级清晰(`#`/`##`/`###`);开头一段定基调/给结论;主体分小节;适当用列表和 **加粗** 突出重点;语言贴合读者,**不堆废话、不为凑字数注水**。

## 5. 自查(必做,别跳)
交付前**通读一遍自己写的**,逐项核:
1. **覆盖度**:用户要求的每个要点/问题都答到了吗?有没有漏。
2. **准确性**:事实和数字对不对、有没有来源;用了附件数据的,和 `read_table` 读到的源**对得上**。
3. **结构**:层级清楚、不重复、过渡顺;扫一眼就懂框架。
4. **篇幅与废话**:长度服务目的;删掉「正确的废话」和重复。
5. **格式**:导出成 docx/html 后能正常用。
发现问题就**针对性改**,改完再过一遍。

## 6. 保存 / 导出
- 想继续编辑、放进知识库 → `save_note(title, content)`。
- 要一个能直接拿走的文件 → `create_document(title, content, format)`,`format` 选 `docx`/`html`/`md`(`content` 就是上面的 Markdown);生成后**自动作为可下载成果**展示。两者可都做。

## 7. 迭代
用户要改时,**针对性改对应小节**(别整篇重写),改完重新 `save_note`/`create_document` 存新版,并再走一遍第 5 步自查。
