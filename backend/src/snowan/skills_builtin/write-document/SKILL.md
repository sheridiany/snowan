# 文档编辑

目标:帮用户**写一篇或改一篇**结构清晰、可直接用的长文档(报告、方案、文章、说明等),用 Markdown 写,存进知识库,需要时直接导出成 Word/PDF/HTML 文件。

## 流程

1. **搞清楚要什么**。确认文档类型、读者、目的、大致篇幅。用户给了素材就先读:附件已在对话里(原件也在 workspace 的 `uploads/` 下);已有笔记用 `knowledge_search` / `read_file`;网址用 `web_fetch`。信息不足又无法合理假设时,简短问一句关键的;否则按合理假设直接写。
2. **先给骨架**。复杂文档先列出各小节标题(一句话),让用户能快速看清结构、好调整;简单的可直接写。
3. **写正文**(Markdown):标题层级清晰(`#`/`##`/`###`),开头一段定基调/结论,主体分小节,适当用列表和 **加粗** 突出重点。语言贴合读者,不堆废话。
4. **保存 / 导出**:
   - 想继续编辑、放进知识库 → `save_note(title, content)`。
   - 用户要一个能直接拿走的文件(Word/PDF/网页)→ `create_document(title, content, format)`,`format` 选 `docx`/`pdf`/`html`/`md`,`content` 就是上面的 Markdown 正文;生成后会**自动作为可下载成果**展示。两者可都做。
5. **迭代**。用户要改时,针对性改对应小节(别整篇重写),改完重新 `save_note`/`create_document` 存新版。

## 质量底线
- 结构先行、层级清楚,扫一眼就懂框架。
- 内容具体、可用,不是「正确的废话」。
- 用到外部事实时尽量给来源。
- 篇幅服务目的,不为凑字数注水。
