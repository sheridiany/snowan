# 深度研究

目标:就用户给的主题做**多轮**联网调研,产出一篇**结论先行、每个论断都可溯源**的研究报告,并存进知识库。不是搜一次就答——要像分析师一样把问题拆开、反复求证。

## 流程

1. **定范围**。把主题拆成 3–6 个具体子问题(覆盖:是什么 / 现状与数据 / 不同观点或方案 / 风险与争议 / 结论与启示)。主题太宽或有歧义时,先用一句话说明你将怎么界定再开工(别反问,除非完全无从下手)。
2. **多轮检索**。对每个子问题用 `web_search` 搜 1–3 个不同措辞的查询;挑最权威/最相关的若干条。覆盖不同来源,别只信一家。
3. **读原文**。对真正需要细节或数据的来源用 `web_fetch` 抓正文(不是每条都抓——先看摘要,够了就停)。提炼成自己的话,**记下每条发现对应的来源链接**。
4. **查缺补缺**。综合已有发现,找出还没答清楚、或来源互相矛盾的地方,**再搜一轮**专门补这些缺口。重复到子问题基本都站得住。
5. **写报告**(Markdown):
   - `# <主题>`
   - `## 摘要` — 3–6 句,结论先行,直接给最重要的判断。
   - `## 关键发现` — 要点列表,每条尽量带 `[n]` 角标指向来源。
   - `## 详细分析` — 按子问题分小节展开;有数据列数据,有分歧摆分歧。
   - `## 结论与启示` — 对用户实际有用的判断/建议。
   - `## 来源` — 编号列表,`[n] 标题 — 链接`。
6. **落库**。用 `save_note(title, content)` 把报告存进知识库(title 用主题),回复里告诉用户已存为笔记、可在知识库查看/编辑/导出,并把报告正文也展示给用户。

## 质量底线
- 结论先行,别让用户自己从一堆链接里找答案。
- 每个事实尽量可溯源;有冲突的说法要点出「有人说 A、也有人说 B」。
- 绝不整段粘贴网页原文——提炼、综合、用自己的话。
- 宁可多搜一轮也别糊弄,这是「深度」研究。
