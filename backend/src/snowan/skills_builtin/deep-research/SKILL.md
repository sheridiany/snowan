# 深度研究

目标:就用户给的主题做**多轮**联网调研,产出一篇**结论先行、每个论断都可溯源**的研究报告,并存进知识库。像分析师一样把问题拆开、反复求证。**铁律:拆题 → 多源搜读 → 补缺 → 验证 → 才成文。**

## 1. 定范围
把主题拆成 3–6 个具体子问题(覆盖:是什么 / 现状与数据 / 不同观点或方案 / 风险与争议 / 结论与启示)。主题宽或有歧义时,先用一句话界定再开工(别反问,除非完全无从下手)。

## 2. 多源检索(求广)
- 每个子问题用 `web_search` 搜 **2–3 个不同措辞**的查询;每个核心子问题**至少落实 2 个相互独立的来源**(别只信一家、别只引一个站)。
- 优先**权威、近期**的来源(官方/一手/知名媒体/论文);留意发布时间,旧数据要标注时点。

## 3. 读原文
对真正需要细节或数据的来源用 `web_fetch` 抓正文(先看摘要,够了就停)。**提炼成自己的话,并记下每条发现对应的真实链接**。只引用你**确实读过**的来源。

## 4. 查缺补缺
综合已有发现,找出还没答清、或来源互相矛盾的地方,**再搜一轮**专门补缺。重复到子问题基本都站得住、关键事实都有来源。

## 5. 验证(必做,别跳)——这是「深度」与「搜一次」的分水岭
成文前,换上**挑刺**的视角逐条核验:
1. **引用真实**:报告里每个 `[n]` 都指向你**实际抓取/读过**的来源——**绝不编造链接或标题**,没读过的不要引。
2. **论断有据**:每个承重事实/数字至少有 1 个来源支撑,关键结论尽量 **2 个独立来源**互证;只有一家说的、或各家说法不一的,**明确标注**「仅 X 称」/「A 说…、B 说…」。
3. **事实 vs 推断分开**:哪些是来源里的事实,哪些是你的综合判断,要让读者分得清。
4. 发现引用对不上、或论断悬空 → 回到第 2/3 步补搜补证,别硬写。

## 6. 写报告(Markdown)
- `# <主题>`
- `## 摘要` — 3–6 句,结论先行,直接给最重要的判断。
- `## 关键发现` — 要点列表,每条带 `[n]` 角标。
- `## 详细分析` — 按子问题分小节;有数据列数据,有分歧摆分歧。
- `## 结论与启示` — 对用户实际有用的判断/建议。
- `## 可信度与局限` — 哪些结论证据扎实、哪些尚不确定/单一来源/时效存疑。
- `## 来源` — 编号列表,`[n] 标题 — 链接`(只列真实读过的)。

## 7. 落库
用 `save_note(title, content)` 把报告存进知识库(title 用主题),回复里告诉用户已存为笔记、可在知识库查看/编辑/导出,并把报告正文也展示给用户。

## 质量底线
- 结论先行,别让用户自己从一堆链接里找答案。
- **绝不编造来源/链接;没读过的不引**;事实与推断分开。
- 绝不整段粘贴网页原文——提炼、综合、用自己的话。
- 宁可多搜一轮也别糊弄;关键结论靠多源互证,这是「深度」研究。
