# Snowan 日记 (Daily Note) — 方向稿

状态:**方向**(已定调,未到 build spec)。多 Agent 全网调研 + Snowan 真实代码核验 + 对抗式挑刺后调和而成,2026-06-21。
核心定调:**主动书写为主的"早计划 / 随手记 / 晚复盘",vault 原生,做成默认主页,串起全 app 的脊梁。**

## 1. 它是什么,为什么是脊梁
一篇**每天写的、带日期的 Markdown 文件**(`notes/daily/2026-06-21.md`):早上写计划、白天随手记、晚上复盘。它替掉被砍的「设计」做**默认落地页**(开 app → 今天这页,find-or-create),把"这条想法放哪"的决策降到零。

两条不可破的原则:
- **书写优先,不是仪表盘。** 整页绝大部分是你的书写区;自动聚合的上下文只是顶部一条**薄、可折叠、只读**的带子(5 秒扫完就交给编辑器)。所有能长期坚持的日记法(BuJo / 深度工作 / Make Time)都是书写优先;一墙小组件只会被瞄一眼然后弃用。
- **笔记是枢纽/索引,不是镜像。** 带子里是可识别的一行行,**深链跳到真东西**(阅读里的文章、对话里的线程、画图、日程事件),绝不把整个模块重渲染进笔记。

为什么对 Snowan 是天选:你已有早计划晚复盘的习惯;Snowan 已有 vault + SQLite 混合索引 + 端侧 embedding。一篇日记落进 vault,**存下的那一刻就被 agent 可搜、可引用**,还是 episodic 记忆最好的原料。参考产品里没人有这个结构性优势,Snowan 原生就有——不用 6 个易碎的 Obsidian 插件拼。

## 2. 模板(早计划 / 随手记 / 晚复盘)
新建当天时**自动套用一套**(用户动作触发,**绝不 cron**)。起步**极简**,你自己加;日记弃用第一杀手是模板变成"晚上的第二份工作"——3~5 段、5~10 分钟封顶。

```markdown
## 🎯 今日 Highlight
<!-- 一件最重要的事(60–90 分钟级)。可让 AI「帮我规划今天」起草。 -->

## ✅ 今日重点(≤3)
- [ ]
- [ ]
- [ ]

## 📥 随手记
<!-- 一行一条: - [ ] 任务 / - 笔记 / 时间开头=事件。别做成表单。 -->
-

## 🌙 晚复盘
- 今天给 Highlight 留出时间了吗?
- 精力如何?
- 哪件事带来愉悦?
- 一个可改进的点?
- [ ] 今日已收尾 ✓
```
- **早计划封顶**:1 个 Highlight + 最多 3 个重点。敞口待办永远"做不完"→ 把页面变成负罪感。硬上限就是重点。
- **随手记一触即记**:GFM `- [ ]`/`-`,每行天然可索引、复选框可勾。**白天不弹表单/弹窗**——重提示只在早晚两端。
- **晚复盘是收尾仪式不是日记**:4 个固定问题 + 一个「今日已收尾 ✓」(深度工作的 shutdown 钩子),最便宜的持久习惯锚。
- **默认不放**:心情/精力/喝水/感恩格、习惯打卡、天气、名言、字数要求。(`mood/energy` 见 §10 决策,默认不进模板。)

## 3. 页面结构:薄组装带 ⊕ 书写区
顶部**薄、可折叠、只读组装带** + 下方**全宽书写区**。不是两栏仪表盘,不是 50/50(那是贬低书写)。NotePlan/Reflect/Tana/Capacities 全收敛到这个形态。

**组装带当场查询(date==今天)实时渲染,绝不写进 `.md` 文件**——只持久化你的正文。把聚合快照写进文件是所有调研一致点名的大忌:会腐烂、复制源、用过时内容污染 KB 索引(然后 agent 还会去引用它)。

带子封顶 **3~5 张紧凑、当日相关、可折叠**的卡(空/折叠时几乎不占高度,编辑器保持在首屏):
1. **今日日程** — 来自日程模块的只读议程行(`calendar.events_on(date)`,§5)。
2. **今日捕获** — 今天读/存的文章(阅读)、今天的对话、今天生成的图(画图),一行一条跳出去。
3. **昨日未完成** — 近几天日记里没勾的 `- [ ]`,只读,每条一键「→ 移到今天」(§7)。
4. **相关记忆 / 往年今日** — 默认折叠,一键展开。

**不进带子**:习惯格、指标、天气、名言、整篇文章/对话/图内容、任何非"今天"的东西。一行若不能链到真实产物,就不该出现。

## 4. vault 存储 + KB 索引
就是一篇普通 vault 笔记,**不另起炉灶**。
- **路径**:`~/.snowan/knowledge/notes/daily/YYYY-MM-DD.md`。需在 `knowledge.py` 改两小处:`_all()` 现在是扁平 `glob("*.md")` → 改 `rglob`/加 daily glob 让子目录进索引;daily 笔记**绕过** `_free_path()`(文件名就是日期,不是 slug)。
- **frontmatter**:`type: daily` + `date` + 可选 `mood/energy`。
- **⚠️ 一个真实 bug(已核验)**:`knowledge.py` 的 `_serialize/_parse` 只认固定字段、**没有 `_extra` 透传**,所以手写的 frontmatter(`type/mood/energy`)在第一次 `update_note` 就被丢掉。`memory.py` 已有现成解法(`_extra`)。**把 `_extra` 模式移植进 `knowledge.py`**——否则 daily 笔记的 vault 保真就是坏的。这是 P1 必修。
- **自动索引**:每次 create/update 都 `index_document(... source_type="note")`,落 `index.db`、端侧 embedding、混合检索(note 权重 1.0)。存即可搜可引。

## 5. 日程对接契约(只消费,不重建)
日程模块拥有事件;在笔记里再做一个日历=两个源,禁止。
- **查询已存在**:`calendar.events_on("YYYY-MM-DD")` 返回当天事件(按开始排序)。在 `/assembly` 端点**服务端调用**,带子一次后端往返。
- **事件形状(契约)**:`id, sourceId, title, startsAt(ISO8601Z), endsAt, calendarName, location, notes, attendees[], url, updatedAt`。只依赖这个 dict。
- **只读上下文**:事件渲染成议程行;你的时间块/计划是你写进正文的 Markdown(NotePlan 模式 `* 17:00 回邮件`),笔记不拥有/不改事件。
- **优雅降级**:`calendar.json` 空或读失败 → `events: []`,空日程也要正常渲染。
- **绝不在开页时自动同步日历**(`calendar.py` 本就反 cron)。读缓存即可;要刷新给个**手动**「刷新日历」(且视觉降权,别放在最常开主页的热区——见风险)。
- **加一层薄校验/adapter**:日程仍在施工,若它改了事件字段名,要在 assembly 边界**一处报错**,而不是整条带子默默空白。
- *核验提示*:两个研究 agent 对日程现状判断不一(一个说路由没注册/函数名不符,一个说已修好)。**真到 build 时以你那边日程的实际代码为准**,依赖只收窄到 `events_on`。

## 6. 按需 AI(只点按触发,绝不 cron)
Snowan 明确砍掉主动层(ROADMAP)。每个 AI 动作都是**按钮 / 光标处 `/` 命令**,无推送、无定时。AI 只当**提问者和总结者,绝不当作者**——产出**草稿供你改/接受**,绝不静默改正文。
1. **帮我规划今天(早)**:聚合今日日程 + 近期工作 + 相关记忆 → 起草 Highlight + ≤3 重点。**⚠️ 防认知外包**:做成"给选项/提问"而非一键接受的成稿,免得"直接接受"扼杀了思考(参考 §10 风险)。
2. **总结我的今天(晚)**:读你今天写的 + 当日活动 → 成就/挑战/一条教训/明日重点的草稿。
3. **按需反思提问**:读当前正文,生成**一个**新的上下文追问(+ 一句起头),只给问题不给答案。
4. **周复盘**(独立 `type: weekly` 笔记 + 「整理本周」按需动作,GTD;**够料才出**)。
- **实现走轻路径**:别走重的聊天 agent;**照搬阅读路由的一次性 Agent 模式**(`server/reading.py` 的 summarize/translate/ask 各起一个聚焦 `pydantic_ai.Agent`)。新增 `POST /api/knowledge/daily/{date}/plan`、`/summarize`。
- 接受进笔记的 AI 块打 `origin: ai` 标记(复用现有 origin 字段),引用所用来源。

## 7. 导航 / UX
- **日期导航**:前/后一天 + 「今天」+ 迷你月历(有笔记的日期打点,`GET …/daily/dates`);键位 T/J/K/G。
- **新一天自动套模板**(用户动作触发,无 cron);页面永不空白吓人。
- **任务滚动——一等公民,但务必"人来决定",绝不静默**:昨日未完成只读上浮 + 每条一键「→ 移到今天」(或经"帮我规划今天")。重写任务本身就是相关性过滤(BuJo 迁移)。无 cron、不堆积。
- **往年今日**:同 MM-DD 文件名查询(不走搜索),一张可折叠卡,点开看;不自动展开、不通知。
- **回收「设计」槽 + 设默认主页**(三处实改):`ListPane.tsx` 把 `View` 的 `'design'`→`'daily'`、`SECTIONS` 那条改成日记项(图标用与日历 `CalendarDays` 区分的,如 `NotebookPen`);`App.tsx` 把 `view==='design'→ComingSoonView` 改成 `'daily'→DailyView`(右栏 guard 决定 daily 不显示知识右栏);`useViewHistory.ts` 把种子 `['conversations']`→`['daily']`(**这一行让"开 app=今天"成真**)。新建 `components/views/DailyView.tsx`、一个编辑器组件、`api/daily.ts`(注意是**扁平 `api/daily.ts`**,不是 `api/modules/daily.ts`)。

## 8. 喂长期记忆(延后,user-triggered)
- daily **笔记**(`notes/daily/`,你写的)与记忆 L1 episodic 日志(`~/.snowan/memory/daily/`,agent 的事件流)是**两个文件,别合并**。笔记存即以 `source_type='note'` 可搜。
- 喂 consolidation 走**接受"总结我的今天"草稿时** `memory.append_daily(...)`(compaction 已有先例)→ 进现有的、需用户批准的整理流。L3 `PROFILE.md` 绝不自动写。
- **这块整体延后**到 P1+P2 留存被验证之后(见 §9)。

## 9. 分期(已按挑刺调整——这是关键改动)
> 挑刺核心:原 P1 把**最难的编辑器**塞进了"第一天就能用"的阶段,且 P1 没有任何"次日回看"的连续性,根本验证不了习惯。修正如下。

- **P1 — 极简但真能用的书写日记(用现有 `Input.TextArea`,先不做花哨编辑器)。**
  - vault:`notes/daily/YYYY-MM-DD.md`;`_all()` 递归;daily 绕过 slug。
  - **修 `knowledge.py` frontmatter `_extra` 丢失**(从 `memory.py` 移植),round-trip `type/mood` 不丢。
  - **定义"今天"**:以**客户端本地日期(开页时)**为唯一真源;跨午夜规则明确(00:30 打开算新的一天);文件名与带子查询用同一定义。
  - 端点:`/daily/today`(find-or-create+模板)、`/daily/{date}`、`/daily/dates`。
  - 前端:回收设计槽 → DailyView;默认主页=daily;日期导航(箭头+今天+月历打点)。
  - 编辑器:**一个最极简、字节稳定的 markdown 编辑器**(裸 `.md` 为源:增强版 textarea,或极简 CodeMirror markdown 源码模式 + 交互复选框只改单行字节)。**不要用 TipTap/ProseMirror 这类 WYSIWYG 当源文件编辑器**——其 markdown 序列化有损,会每次改动重排字节→反复重嵌入+脏 git diff(留作以后富输入,且 round-trip 验证过再用)。CJK/IME composition 必须先验证。
  - **次日连续性放进 P1**(挑刺必修):哪怕只是只读「昨日未完成」+ 手动复制,或顶部一行「昨日:<链接>」——否则 P1 验证的是"好不好写",不是真正的习惯(回看→续写)。
  - 自动保存:~1.5s + 失焦保存 + 「已保存 HH:MM」;**先做 mtime 冲突检测**(buffer 打开期间文件被 Obsidian/git 改了 → 提示/合并,别盲覆盖)再谈"字节稳定"。
  - *出口*:开 app 到今天,能写早计划/随手记/晚复盘、勾任务、翻天、看到昨日未完成。无组装、无 AI。

- **P1.5(可选打磨)— 书写体验升级。**
  - 若 P1 的极简编辑器够用,这阶段可省。要升级再上 CodeMirror-6「源码 + 只读装饰」(Obsidian 模式),仍守字节稳定 + 交互复选框只改单行 + IME 已验证。

- **P2 — 组装带 + 日程 + 按需 AI。**
  - `/daily/{date}/assembly`:服务端 `events_on`(降级 `[]`)+ 今日阅读行 + 相关记忆;今日对话/图行**前端本地**拼(对话/图是前端 localStorage 拥有,后端没有"今天创建"查询——P2 不要去造)。
  - 折叠带 UI + 深链;AI `plan-my-day`/`summarize-my-day`(阅读路由一次性 Agent 模式,出可编辑草稿,标 `origin:ai`)。

- **P3(留存验证后再说,不进承诺路线)** — 周复盘、往年今日、记忆喂入、按需反思提问、贡献热力图(永不做火苗/打卡施压)。

## 10. 明确不做(YAGNI / 反模式)
无 cron/心跳/自动晨计划推送/复盘催促(AI 只点按);不把组装写进 `.md`;不在笔记里重建日历;AI 不代写正文、不说教、不让聊天来主持日记;不静默自动滚动任务(任务债坟场);无配置面板/插件拼装/前置 schema(开箱即用、有主见);组装带不堆杂货;不做 Duolingo 式打卡施压;早期不造"今天的对话/图"后端查询(前端拼,直到有 created-at 元数据再说);模板不超 5 段。
